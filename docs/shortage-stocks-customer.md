# API: Принятие изменений по дефициту остатков

## POST /orders/:id/accept-shortage

Эндпоинт для клиента (владельца заказа). Клиент принимает предложенные администратором изменения количества товаров.

## Аутентификация

- Требуется JWT токен
- Только владелец заказа (`create_user_id`)

## URL Parameters

| Параметр | Тип | Описание |
| -------- | --- | -------- |
| id | int | ID заказа |

## Request Body

Пустое. Тело запроса не отправляется.

```
POST /orders/42/accept-shortage
Content-Type: application/json

{}
```

## Логика

При вызове эндпоинта выполняется:

1. Проверка: статус заказа = `new` или `processing`
2. Проверка: `shortage_stocks` не пустой
3. Для каждой позиции из `shortage_stocks`:
   - Уменьшение количества в `order_product`
   - Освобождение лишних резервов на складах
4. Пересчёт итогов заказа:
   - `subtotal` = сумма (новое_количество x старая_цена)
   - Скидки пересчитываются по новой сумме
   - `total` = subtotal - discount_total + delivery_price
5. Очистка `shortage_stocks` = `[]`
6. Если статус `processing` — отмена и пересоздание трансферов

**Цена за единицу НЕ изменяется** — остаётся на уровне момента создания заказа.

## Response (успех)

```json
{
  "data": null,
  "status": "success",
  "errors": [],
  "message": "Изменения по остаткам приняты"
}
```

## Response (ошибка)

```json
{
  "data": null,
  "status": "error",
  "errors": [],
  "message": "Нет изменений по остаткам для принятия"
}
```

## Отмена заказа

Отмена заказа при дефиците остатков выполняется через отдельный эндпоинт:

```
PATCH /orders/:id/reject
{
  "rejected_reason": "Не устраивает изменённое количество"
}
```

## Примеры сценариев

### Клиент принимает изменения

Заказ был: Товар А — 20 шт, Товар Б — 10 шт
Дефицит: Товар А — 12 шт, Товар Б — 10 шт (без изменений)

После принятия:
- Товар А: quantity = 12, price = старая цена
- Товар Б: quantity = 10, price = старая цена
- totals пересчитаны

### Одна позиция с quantity: 0

Дефицит: Товар А — 0 шт

После принятия:
- Товар А: quantity = 0, price = старая цена
- totals пересчитаны без этой позиции

### Все позиции с quantity: 0

После принятия:
- Все товары: quantity = 0
- subtotal = 0, total = delivery_price (или 0 если pickup)
- Заказ остаётся в статусе `new`/`processing`
- Клиент может отменить заказ позже

## Ограничения

- Эндпоинт доступен только в статусах `new` или `processing`
- Если `shortage_stocks` пуст — ошибка (нечего принимать)
- Если статус изменился пока клиент просматривал дефицит — ошибка
