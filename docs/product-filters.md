# Фильтры каталога

`GET /product/filters` — публичный эндпоинт с `OptionalJwtAuthGuard`; без токена роль `user` (`product.controller.ts:60-101`). Код: `product.service.ts:597-844`, тесты: `src/product/test/product.service.getFilters.spec.ts`.

## Параметры (все необязательны)

`category_id` (категория + потомки), `search` (ILIKE по имени/описанию), `product_types` (CSV), `country` (CSV), `price_from` / `price_to`, `specifications` (CSV `id:value`, значения одного id — «ИЛИ», разные id — «И»; некорректные пары игнорируются).

Ответ: `{ data: { price: {min,max}, specifications: [{id,name,type,values}], countries, product_types } | null, status, message, errors }`. Пустая выборка — `price: {min:0,max:0}` и пустые массивы.

## Логика

- Четыре последовательных параметризованных SQL-запроса: цена, страны, типы, характеристики. База — видимость товара из `buildMainPageWhere` (остаток + цена > 0; для `user` — публичный тип).
- В фасете цены агрегат `MIN(pp.price)` для staff, `MAX(pp.price)` для `user`, **без фильтра `isPublic`** — `isPublic` влияет только на видимость товара. Диапазон считается по `product_price` с `price > 0`.
- Каждый фасет исключает свой фильтр, чтобы не «съесть» альтернативы; фасет характеристик, наоборот, учитывает выбранные характеристики.
- Характеристики скрыты, если выбрано >1 типа товара или тип не выбран, но доступно >1 типа. Показываются только значения с `COUNT(DISTINCT value) > 1` (или выбранные), максимум 5, активные выше; технические (`Артикул`, `Штрих-код`, `Код товара`) исключены.

Примеры ответов в прежней версии документа были сняты с локальной БД и не являются фиксированными фикстурами.
