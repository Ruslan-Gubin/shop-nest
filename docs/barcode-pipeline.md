# Barcode Pipeline: штрих-код → карточка товара

## Общий принцип

Процесс автоматизированного заполнения карточки товара. Администратор вводит **штрих-код** (EAN-13) или **название товара**. Система ищет данные в интернете, извлекает характеристики, заполняет форму. Администратор получает уже готовый вариант и может применить.

Если введён штрих-код — система сначала пытается найти название по нему. Если название не найдено — процесс останавливается с просьбой указать название вручную. Если введено название напрямую — поиск по штрих-коду пропускается.

---

## Этап 1. Получение названия

**Вход:** два возможных варианта:

- `barcode` — строка цифр (EAN-13). Если передан — система ищет название по нему.
- `name` — строка названия товара. Если передан — система использует его напрямую, без поиска.

**Логика:**

- Если передан `barcode` → поиск названия по штрих-коду (разделы 1.1–1.4)
  - Название найдено → приводим к чистому виду → переход на Этап 2
  - Название НЕ найдено → **СТОП**. Ответ: `"По данному штрихкоду не удалось найти название товара. Укажите название товара вручную"`
- Если передан `name` → сразу переход на Этап 2 (поиск данных по названию)
- Если не передан ни `barcode`, ни `name` → ошибка: `"Укажите штрих-код или название товара"`

### 1.1 Поиск на ean-online.ru

```
POST https://ean-online.ru/match.php
Content-Type: application/x-www-form-urlencoded
X-Requested-With: XMLHttpRequest
Referer: https://ean-online.ru/
User-Agent: Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36

body: barcode={barcode}
```

**Ответ:** строка с названием товара или пустая строка (если не найден).

### 1.2 Поиск на ru.disai.org

```
GET https://ru.disai.org/?search_query={barcode}
User-Agent: Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36
```

**Парсинг ответа:** найти текст между `"Введенный Вами GTIN ... соответствует символике EAN-13:"` и концом строки или следующим тегом. Это название товара.

### 1.3 Поиск на barcode-list.ru

```
GET https://barcode-list.ru/barcode/RU/Поиск.htm?barcode={barcode}
User-Agent: Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36
```

**Парсинг ответа:** из HTML-таблицы извлечь строки, где `<td>` содержит наименование товара. Берётся первая запись с наивысшим рейтингом (колонка "Рейтинг"). Текст названия находится внутри ячейки с наименованием.

### 1.4 Поиск на Яндекс.Маркете

```
GET https://market.yandex.ru/search?text={barcode}
User-Agent: Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36
```

**Парсинг ответа:** из HTML-разметки извлечь названия товаров из карточек результатов поиска (элементы с названиями товаров). Если найдено несколько вариантов от разных продавцов — выбирается наиболее часто встречающееся название как наиболее достоверное.

### 1.6 Приведение названия

Названия из разных источников или введённое админом название могут содержать лишние символы, опечатки, нестандартный регистр. Привести к единому чистому виду можно через AI.

**Промт для случая barcode (несколько источников):**

```
У меня есть названия товара из разных источников:
- "{name1}"
- "{name2}"

Приведи к единому чистому названию для интернет-магазина.
Удали лишнее, приведи к нормальному регистру.
Верни ТОЛЬКО название, без пояснений.
```

**Промт для случая прямого ввода названия (один источник):**

```
Проверь название товара на опечатки и приведи к нормальному виду для интернет-магазина:
"{name}"

Исправь орфографические ошибки, приведи к нормальному регистру, удали лишние символы.
Верни ТОЛЬКО исправленное название, без пояснений.
```

Приведение применяется в обоих случаях — и при поиске по barcode, и при прямом вводе названия админом.

## Этап 2. Поиск данных по названию

**Вход:** `cleaned_name` из Этапа 1 (получен либо по barcode, либо напрямую от админа).

### 2.1 Обязательный проход по источникам

Система **обязательно проходит по всем источникам** из списка ниже, независимо от того, найден товар или нет.

После прохода по всем источникам формируется единое описание, которое передаётся на следующий этап.

| №   | Источник                                                                                           | Метод запроса                      | Что ожидаем                                      |
| --- | -------------------------------------------------------------------------------------------------- | ---------------------------------- | ------------------------------------------------ |
| 1   | Яндекс / Google (через поисковый API)                                                              | Поисковый запрос по `cleaned_name` | Ссылки на карточки товаров, фото                 |
| 2   | Сайты с отзывами (IRecommend, Otzovik)                                                             | Поиск по названию + бренду         | Отзывы пользователей, детали использования, фото |
| 3   | Маркетплейсы (Ozon, Wildberries)                                                                   | Поиск по названию                  | Характеристики, размеры, вес, цена, фото         |

С каждого найденного источника дополнительно собираются изображения товара — см. шаг «2. Изображения» в разделе 2.2.

### 2.2 Сбор данных с каждой страницы

Каждая найденная страница (отзыв, карточка магазина, агрегатор и т.д.) содержит часть информации о товаре. Со страницы собираются два типа данных:

**1. Текст:** через AI извлекаем описание товара (просто текст, без разделения на поля).

**2. Изображения:** при парсинге страницы собираются **все URL изображений**, относящихся к товару:

- `<meta property="og:image">` — основное изображение
- `<img>` внутри карточки товара (фото, галерея, слайдер)
- Изображения из блоков с классом/id, содержащим `gallery`, `slider`, `product-image`, `photo`

Собранные ссылки складываются в общий массив `photos`. Дубликаты URL удаляются.

**Важно:** URL изображений собираются **только из реального HTML/API страницы**. Запрещается выдумывать ссылки или использовать placeholder-URL. Если на странице нет изображений — шаг пропускается. Если ни один источник не дал фото — `photos: []`.

**Промт для одной страницы:**

```
Ниже текст страницы с информацией о товаре "{name}".
{text}

Составь описание этого товара на русском языке на основе текста.
Включи в описание ВСЕ упоминания:
- внешний вид, материал, размеры, вес
- комплектацию
- бренд, категорию
- характеристики и особенности
- страну производства
- любые другие детали

Не придумывай ничего от себя — только то, что есть в тексте.
Описание должно быть связным и читабельным.
```

Результат от каждой страницы — текстовое описание. Например, с IRecommend пришло описание внешнего вида, с Ozon — характеристики и вес, с Wikipedia — бренд и категория.

### 2.3 Слияние в единое описание

После того как собраны все доступные описания, AI объединяет их в **одно полное описание товара**, которое вбирает всю информацию из всех источников без потерь.

**Промт для слияния:**

```
У меня есть несколько описаний товара "{name}" из разных источников.

=== Источник 1 (IRecommend) ===
{text_from_source_1}

=== Источник 2 (Ozon) ===
{text_from_source_2}

=== Источник N ===
{text_from_source_N}

Объедини все описания в ОДНО полное описание товара на русском языке.
Правила:
- Включи ВСЕ детали из всех источников (описание, характеристики, размеры, комплектацию, бренд, категорию, страну производства)
- Если одна и та же информация повторяется — возьми самую подробную формулировку
- Не придумывай ничего от себя
- Описание должно быть связным, читабельным, в виде текста (не списка)

Верни ТОЛЬКО итоговое описание, без пояснений.
```

**Это единое описание становится единственным источником данных для Этапа 3.** На Этапе 3 из него будут извлекаться структурированные поля (бренд, категория, характеристики, вес, размеры и т.д.).

**Если ни один источник не дал текста (все статусы `not_found` или `blocked`) → `description = null`.** В этом случае на Этапе 3 AI не выдумывает данные, а выставляет все поля в null.

## Этап 3. Компоновка в структуру Product

**Вход:** данные Этапа 1 (`cleaned_name`, `barcode`, `country`) + единое описание товара из Этапа 2.

### 3.1 Извлечение структурированных полей из описания

Единое описание товара (из Этапа 2) отправляется AI для извлечения структурированных данных.

**Важно:** Если `description` из Этапа 2 равен `null` (ни один источник не дал данных) — AI **не выдумывает** информацию. Все поля в JSON возвращаются со значением `null`, генерация SEO на Этапе 3.2 также пропускается.

**Промт:**

```
Ниже полное описание товара "{name}".
{единое_описание_из_этапа_2}

Ты — менеджер по продажам в крупной компании. Твоя задача — дать официальное, формализованное описание товара.

Извлеки из описания следующие поля и верни ТОЛЬКО JSON без пояснений:

{
  "description": "Описание товара (5-6 предложений, официальный стиль, с деталями и нюансами)",
  "product_type": "Вид товара (например \"Кукла-пупс\", \"Тетрадь\")",
  "equipment": "Комплектация (что входит в набор)",
  "brand_name": "Бренд",
  "category_name": "Полный путь до листовой категории (например \"Игрушки / Куклы / Кукла-пупс\" или \"Посуда / Чайники / Эмалированные чайники\")",
  "specifications": [
    { "name": "Название характеристики", "value": "Значение" }
  ],
  "weight": число (вес в граммах) или null,
  "height": число (высота в см) или null,
  "length": число (длина в см) или null,
  "width": число (ширина в см) или null,
  "country": "Страна производства" или null
}

Если данных для поля нет — ставь null.
Не придумывай от себя ничего, чего нет в описании.
```

### 3.2 Генерация SEO-данных

**Вход:** структурированные поля из Этапа 3.1 (`name`, `description`, `brand_name`, `category_name`, `specifications`).

AI генерирует SEO-данные на основе этих полей:

**Промт:**

```
Название товара: "{name}"
Бренд: "{brand_name}"
Категория: "{category_name}"
Описание: "{description}"

Сгенерируй SEO-данные для этого товара и верни ТОЛЬКО JSON без пояснений:

{
  "seo_title": "Meta-заголовок (до 60 символов, с ключевыми словами)",
  "seo_description": "Meta-описание (до 160 символов, с ключевыми словами)",
  "slug": "ЧПУ-строка (транслит, только латиница, дефисы вместо пробелов, без спецсимволов)",
  "og_title": "Open Graph заголовок (до 60 символов)",
  "og_description": "Open Graph описание (до 160 символов)",
  "og_type": "Тип Open Graph (обычно 'product')",
  "keywords": "Ключевые слова через запятую (5-10 слов)"
}
```

## Правила работы

При работе с реальным баркодом или названием товара все шаги пайплайна выполняются **последовательно** от Этапа 1 до Этапа 3.

**Запрещается:**

- Пропускать этапы
- Выдумывать данные, которых нет в источниках
- Использовать placeholder/заглушки вместо реальных данных
- Добавлять поля, не предусмотренные схемой результата

Если на каком-либо шаге данных нет — поле остаётся `null` или `[]`. Итоговый JSON формируется строго по схеме из раздела «Результат Этапа 3».

## План: сбор результатов в БД

_Пока не реализовано. Опционально, добавить при внедрении БД._

При поступлении запроса (barcode или название товара) система проверяет, есть ли уже собранный результат для этого `search_key`:

```
Запрос (barcode или cleaned_name)
       │
       ▼
БД: поиск по search_key
       │
       ├── найдено → вернуть сохранённый JSON
       │
       └── не найдено → полный цикл Этап 1→3
                        → сохранить результат в БД
                        → вернуть JSON
```

**search_key** — уникальная строка: код EAN (13 цифр) или `cleaned_name` товара.
